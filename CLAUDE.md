# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**SelfBalance Lab** (briefly branded "JARVIS", and "GYRO" before that) — a zero-build, browser-based **robotics creator space**. You drag electronic components onto a bench, wire their pins, and watch a **real DC-circuit solver** light LEDs, throttle motors, and flag shorts — then hit **RUN** to drive the wired motor in a Rapier physics sim. A natural-language assistant (**Hephaestus**) can build and wire the circuit for you. Everything is static files and ES modules; all deps load from CDN via the import map in `index.html`. There is no build step; the only backend is one stateless Vercel Edge function that proxies Hephaestus to the Gemini API (the app runs fully without it). (`package.json`/`node_modules` exist only for dev tooling — Playwright, ESLint, the `serve` script.)

**The pivot (mid-2026), now complete:** the app was a fixed self-balancing-robot *curriculum* (guided Assemble→Wire→Program→Run with ~20 lessons). It is now an open creator sandbox built around a single mutation authority, `window.__api`, backed by a `RobotDoc v2` document and an MNA circuit solver.

**The pre-pivot stack has been deleted** (2026-08-03) — don't go looking for it. Gone: the curriculum engine + lessons, the Guide rail, missions, the CodeMirror firmware editor and Serial Monitor (the sketch was never executed — the controller was JS — so the panel showed code that did nothing), the `js/robots/` RobotDef registry + robot picker, the `BalanceSim`/`RoverSim` arena in `js/sim.js` (only `loadRapier` survives, as `js/sim/rapier.js`), the old slot-based `assembly.js`/`wiring.js`, the v1 `save.js`, WASD driving input (`input.js`/`touch.js` — RUN is a motor test, not a driving game), and the dormant `assets.js` model-override workflow. `js/parts.js` keeps only the two meshes the bench reuses. **`js/app/classroom.js` and `cloud.js` were deliberately kept** — the teacher/roster layer is the payer path, not curriculum debt.

## Running

Serve the folder statically and open the printed URL (needs WebGL + WebAssembly):

```bash
npx serve .          # or: python -m http.server 8000
```

Verification: `npm test` runs the Playwright suite headlessly with software WebGL — run it before committing. The **creator-era specs are the ones that matter**: `tests/circuit.spec.js` (the solver: open/closed/reversed/resistor/switch/LED/short + live Inspector edits), `tests/smoke.spec.js` (inspector + tray + doc→3D fusion), `tests/hephaestus.spec.js` (mocked Gemini tool loop + free-tier quota gate), `tests/mobile.spec.js` (the phone shell + the touch gestures, at a 390×664 viewport — and one case at 1280×800 asserting the desktop cockpit is untouched). `npm run lint` runs eslint. The single debug/authority hook is **`window.__api`** (see `js/api/index.js`) — tests, the UI, and Hephaestus all drive it; mutations return `{ok, changed, errors}` and take `{dryRun}`. Headless WebGL runs slower than real time, so tests must poll state, not use fixed waits. Deployed to Vercel (production = `master`; project `selfbalance-lab`, GitHub repo `self-balance-lab`).

## Architecture (creator layer — the live product)

- **`window.__api` / `js/api/index.js`** (`createApi`) — the **single mutation authority**. Every change to the build funnels through it: `place_component`, `remove_component`, `move_component`, `connect`, `disconnect`, `set_param`, `set_name`, `undo`/`redo`, plus reads `get_document`/`read_electrical`/`read_telemetry`/`validate`. Mutations are shaped so a JSON-schema tool def is a mechanical transform of the signature. The DOM layer holds NO mutation logic — it calls the API and re-renders from the returned doc via the `onDocChange` hook. Wraps a `DocHistory` (undo/redo/dry-run) over `js/model/patch.js` (the only place the doc mutates; ops: add/remove-component, set-param, set-transform, add/remove-edge, set-name/code).
- **`js/model/`** — the document layer. `doc.js` = `RobotDoc v2` (`{ v:2, robotId, name, components[], nets[], code?, sim, meta }`; endpoint ids `"compId.pin"`; nets = union-find over wire edges). `library.js` = the component registry (16 types: battery, motor, resistor, switch, led, potentiometer, push_button, lamp, buzzer, diode, photoresistor, thermistor, fuse, capacitor, servo, relay) — pins, pin roles (`power+`/`power-`/`signal`/`gnd`), and default electrical params. (The potentiometer is a rheostat — a variable resistor whose knob sets `resistance`; scroll on its 3D knob or edit it in the Inspector.) It's the single source the tray, the geometry, the solver, and Hephaestus's tool enum all derive from, so adding a component here surfaces it everywhere.
- **`js/sim/circuit.js`** — the **DC circuit solver** (Modified Nodal Analysis). Ground = node 0; each component maps to primitive elements (`R` resistor, `V` ideal source + series R via an internal node, `D` piecewise-linear diode) via `COMPONENT_ELECTRICAL`. Batteries/motors are `V` sources (motor back-EMF = `Ke·ω` is a known source at solve time); resistor/closed-switch are `R`; the **LED is a nonlinear diode** resolved by iteration (assemble → flip inconsistent diodes → re-solve). Returns `{ nodeV, current:{compId}, violations[], ok }`, detects shorts/over-current, and `motorTorque()` turns the solved current into physics torque. Pure math, no THREE/DOM — importable server-side.
- **`js/app/creator-assembly.js`** (`initCreatorAssembly`) — the fused build surface: placement + wiring as a pure **view over `api.get_document()`**. Tray drag → `place_component`; pin→pin click → `connect`; **right-click a wire to delete it, right-click a part to remove it**; **drag a placed part to move it** (`move_component`); **R rotates** the hovered/dragged part about Y (yaw is doc-driven, physics-locked); click a switch body to toggle it. `sync()` reconciles 3D meshes with the doc (called from the API's `onDocChange`). Component geometry comes from local `FACTORY`/`CARD` tables (battery/motor/resistor/switch/led); wires are bezier tubes built from `doc.nets`, colored by pin role. **Touch gestures (the mouse verbs have no touch equivalent otherwise):** a **long press** (500ms, cancelled by any real finger travel) removes the part or wire under the finger — the right-click stand-in; a **double tap**, matched by *component* rather than by exactly what's under the finger, rotates it — the R-key stand-in; a **tap on a tray card** (a drag of zero length) places the part on the bench rather than at the hidden point under the sheet, and pin picking gets a bigger screen-space snap radius on coarse pointers. The touch paths key off the in-flight `pointerType`, not a media query, so a hybrid laptop answers to both its trackpad and its screen. **Bench physics (real Rapier gravity in the BUILD view):** `initBenchPhysics()` runs a second Rapier world — every placed part is a dynamic box body (footprint collider, rotations locked so parts stay upright) on a ground plane with low walls, so parts **fall onto the bench, collide, and stack**. `animate()` steps that world, copies body translations → meshes, and rebuilds wires while anything's awake; the doc transform stays the persisted "rest" pose (committed on drag-release). Dragging drives a kinematic body; release drops it. Separate from the RUN sim (`creator-sim.js`) — this world only steps in assembly mode. **Live electronics→physics feedback in build mode:** wire charge-flow speed/visibility tracks the solved current, LED lenses glow ∝ current, and a powered motor's wheel visibly spins (bright cross-spokes make it read) — all off the circuit solve, before entering the sim.
- **`js/app/coach.js`** (`initCoach`) — the first-run onboarding coach: a 5-step "build your first circuit" checklist (place battery → place motor → wire + → close the loop → RUN) that advances by deriving each step's done-ness from the live `api.get_document()`/`read_electrical()`/`state.mode` — it owns no state. Self-retires (and persists `sbl-coached` in localStorage) once completed or dismissed; `pointer-events:none` so it never blocks the 3D view.
- **`js/app/inspector.js`** (`initInspector`) — the DOM window into the live doc + solve (read + a **live param editor**). Polls `get_document`/`read_electrical`/`read_telemetry` (~400ms) and renders components (with solved current ▲/▼ + ω), nets, and violations (or "✓ Circuit OK"). Each component exposes its tunable params (resistance, volts, Vꜰ, I-max, switch closed…) as inline fields via a `PARAM_META` allowlist; editing one calls `set_param` and the solve updates. A focus guard stops the poll from clobbering a field mid-keystroke. This replaced the deleted Guide rail as the on-screen home for the electrical solve.
- **`js/sim/creator-sim.js`** — the RUN-mode physics: a motor-bench body driven by the solved motor current/torque. `main.js` builds it, feeds it the circuit solve, and streams `{ omega }` back through the API's telemetry hook (so the Inspector shows live ω and LEDs/motors react).
- **`js/api/tools.js` + `js/app/hephaestus.js` + `api/hephaestus.js`** — the **Hephaestus** natural-language assistant. `tools.js` is the canonical tool contract (`geminiFunctionDeclarations()` derived from `window.__api` + `LIBRARY`; `TOOL_EXECUTORS`; `runTool`; `SYSTEM_PROMPT`). `api/hephaestus.js` is a stateless Vercel **Edge** function that proxies to **either OpenRouter or Gemini** and always answers in the Gemini `parts` shape, so the client never knows which ran and the provider is one env var away (`OPENROUTER_API_KEY` wins when set, default model `deepseek/deepseek-v4-flash` — chosen because `bench/` scored it 27/29 blind on this same tool contract; otherwise `GEMINI_API_KEY` + `gemini-3.5-flash-lite`). Returns 503 if neither key is set, surfaces 429 quota. **The endpoint is public and unauthenticated — on a paid OpenRouter key that is real spend, so cap the key.** `hephaestus.js` runs the client agent loop (functionCall → `runTool` → functionResponse) with a localStorage free-tier quota gate (`FREE_DAILY` msgs/day; pro uncapped). Keys live only in Vercel env / a git-ignored `.env.local` — never committed.

## Architecture (supporting layer)

One Three.js scene, one `mode` flag (`'assembly'` | `'sim'`) in `js/app/state.js` — a tiny pub/sub store (`state`, `set`, `subscribe`) that gates the pointer handlers and the render loop. That flag is now the *only* cross-module state; everything else lives in the document.

- **`js/main.js`** — thin orchestrator: creates the scene + `CreatorSim`, initializes the app modules, builds `window.__api` and hands its `onDocChange` to the 3D sync / topbar / activation metric, owns the RUN ↔ bench transitions (`enterSim`/`exitSim`), the one place the bench camera is composed (`frameBench()` — boot, `exitSim()` and the phone-shell layout swap all land on the same shot, and viewports much narrower than they are tall get the camera backed off) and the single `animate()` render loop (which calls `composer.render()`, not `renderer.render()`, and advances `floorUniforms.uTime`). `enterSim()` coalesces concurrent callers onto one promise and lets failures propagate — `api.run_sim()` is `await`able and resolves only once the sim is really running.
- **`js/scene.js`** — `createScene(canvas)` returns `{ renderer, scene, camera, controls, resize, composer, floorUniforms, assemblyDecor, bloom, studioLights }`. Owns lights, the `EffectComposer` bloom pipeline, and the shader "instrument studio" backdrop. **Emissive materials glow because of the `UnrealBloomPass`** — that's why accents use `emissive`/`emissiveIntensity`. `assemblyDecor` is the list of build-only meshes main hides during RUN. (`slotMeshes` is now an empty map — the fixed-chassis slot ghosts went with the pre-pivot robot.)
- **`js/app/bench-room.js` / `bench-scan.js` / `bench-splat.js` / `room-assets.js` / `props.js`** — the desk-room the bench sits in. `bench-room.js` is the modeled PBR reconstruction (CC0 glTF props + HDRI, the default); `bench-scan.js` is the photogrammetry variant, **hidden on the live site** — it and its `#room-toggle` only exist under `?scan` (or `?scanfit` for the re-bake flow), so its 3.9 MB glTF is never downloaded by a normal visitor; `bench-splat.js` is an inert Gaussian-splat hook (costs nothing unless `?splat=` is supplied); `props.js` adds the interactive desk objects.
- **`js/app/hud.js`** — tooltips, transient status flash, the connection checklist, the sound toggle, and the compact RUN card (title + Reset + back-to-bench). Also reveals `#overlay`, the first-visit welcome.
- **`js/app/mobile.js`** (`initMobileUI`) — the **phone shell** (≤820px, `body.is-phone`). The desktop cockpit is tray | bench | run panel; stacked into three rows on a phone that left the 3D bench about 130px tall with RUN below the fold. Below 820px the bench goes full-bleed and the panels become one bottom **sheet** with tabs (Parts / Circuit / Hephaestus) in a fixed bottom bar, where RUN also lives. It is a pure *layout* module: it wraps `#left-panel`'s children into two groups, **moves** existing nodes (`#upload-btn` into the bar, the canvas' round buttons into the top bar — a moved node keeps its listeners, so nothing is re-wired or duplicated) and toggles classes; everything reverts above 820px, so a rotated tablet or a resized window is fine. It also publishes the real `visualViewport` height as `--app-h` for browsers without `dvh`, and calls back on `'enter'`/`'leave'` so `main.js` can `resize()` and re-frame the bench. In landscape the sheet becomes a side drawer (CSS only). CSS lives in the PHONE SHELL block at the end of `css/style.css`; the old `@media (max-width: 600px)` stack is kept, scoped to `body:not(.is-phone)`, as the no-JS fallback.
- **`js/app/storage.js`** (`migrateStorageKeys`) — one-time localStorage key migration, called first in `main.js`. Saved state used to be split across `sbl-`, `jarvis-` and `gyro-` prefixes; it is all `sbl-*` now, and this copies each old key onto its new name (once) so the rename doesn't silently un-dismiss the coach or hand out a fresh day of assistant quota.
- **`js/app/docsave.js`** — `RobotDoc v2` persistence to `localStorage` (debounced) plus the shareable `#build=` URL (`shareUrl()`, copied by `#share-btn`). Migrates v1 saves on load.
- **`js/app/cloud.js` / `account.js` / `classroom.js`** — the account + teacher layer, live on Supabase. `cloud.js`: magic-link auth, last-write-wins document sync per `kind` with a localStorage-backed offline queue (local-first — `localStorage` stays source of truth). `account.js`: the top-bar sign-in chip + popover. `classroom.js`: a teacher creates a class (6-char join code), students join by code (`create_class`/`join_class` SECURITY DEFINER RPCs), teacher sees an RLS-scoped roster with CSV export. **Kept through the pivot on purpose** — this is the payer path. Lesson/progress sync is gone; only the build document (`kind:'save'`) syncs.
- **`js/app/analytics.js`** — the funnel: `load → place → connect_ok → circuit_ok → run_enter` (+ `share`, `hephaestus_msg`, `hephaestus_tool`). **`circuit_ok` is the activation metric** — fired from `main.js`'s `checkActivation()` on the first solve that is `ok` *and* pushes real current through a non-source component, so it can't be reached by clicking around. Sink is PostHog, locked down for minors (cookieless, `autocapture:false`, session recording disabled, `person_profiles:'identified_only'`); a CDN failure silently falls back to a no-op sink and buffered events replay.
- **`js/app/errors.js`** — `installErrorBoundary()` (called first in `main.js`) pipes global `error`/`unhandledrejection` into `window.__gyroErrors` behind a swappable sink; `isWebGLAvailable()` gates boot and `showFatal()` reveals the `#fatal` fallback.
- **`js/app/quality.js`** — device tier (`'high'|'low'`, override with `?quality=`), resolved once at boot; caps pixel ratio and softens bloom on weak devices.
- **`js/app/perf.js`** — dev-only FPS/frame-time HUD (`?perf` or Alt+P), own rAF loop; `window.__perf.mark(label)` records one-shot timings (main marks `'rapier'`).
- **`js/app/topbar.js`** — brand mark, the open build's name (click to rename via `set_name`), light/dark theme toggle (`data-theme` on `<html>`, persisted).
- **`js/app/examples.js`** — the example-circuit gallery; scripted builds loaded through the same API.
- **`js/sim/rapier.js`** — the shared Rapier WASM loader (one init, whichever of the two physics worlds asks first).
- **`js/parts.js`** — the two detailed meshes the bench reuses (`makeMotor`, `makeBattery`); `creator-assembly.js` builds the rest procedurally. **1 unit = 1 cm.**
- **`js/labels.js`** — canvas-texture flat text labels used by parts.
- **`js/glossary.js`** — plain-language `COMPONENTS`/`PINS` dictionaries keyed by `type` and `"compType.pin"`; drives the hover tooltips. Add a pin here when you add one to the library.
- **`js/audio.js`** — synthesized WebAudio sound design (oscillators + envelopes, no samples — CSP-safe). Singleton `audio`; must be `resume()`d from a user gesture. UI cues plus a motor hum that tracks wheel speed. Mute persists.
- **`mcp/`** — the MCP server exposing the solver + document API to other agents (`server.js`, `workspace.js`, `tools.test.mjs`). It imports `js/sim/circuit.js` and `js/model/` **unchanged** — that's the payoff of keeping them free of THREE/DOM, and it gives the solver browserless CI. `run_sim`/`stop_sim` are deliberately not exposed.

## Conventions

- Vanilla ES modules only — no framework, no bundler. Keep new deps on the CDN import map.
- **Every mutation goes through `window.__api`.** UI modules read the doc and call the API; they never mutate. `js/model/patch.js` is the only place the document actually changes.
- **Keep the solver pure.** `js/sim/circuit.js` and `js/model/` must not import THREE or touch the DOM — that's what lets `mcp/` run the identical solver server-side instead of a second implementation that drifts.
- 1 unit = 1 cm. +Z is "forward".
- When touching materials, remember the bloom pass: brightness of glows is driven by `emissiveIntensity`, and the whole scene renders through `composer`.
- Adding a component = adding it to `js/model/library.js`. The tray, the geometry lookup, the solver and Hephaestus's tool enum all derive from it.
