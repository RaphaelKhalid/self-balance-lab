# SelfBalance: an AI invention studio for kids

The first audience is ages 10–14. The first promise is simple: describe a little invention, build it from real electronic parts, then change it and discover what happens.

“Lovable for kids” is useful shorthand for the creation loop. The product’s distinct starting point is physical inventions: visible parts, real circuits, and immediate cause and effect. It does not yet create arbitrary apps, games, robots, firmware, or printable hardware.

## A 90-second demo

1. Open the studio on Pocket breeze. The fan, switch, battery and control knob are a real wired build. Name it as a starter invention, not something the AI just generated.
2. Turn the power dial down. Switch it off and back on. Point out that the current changes with the circuit.
3. Press RUN. The same invention stays on the desk, now coupled to motor physics. Change the dial again. Keep building returns to editing.
4. With the AI endpoint connected, ask: “Make a light I can switch on. Name it Moon lamp.” Let the live tool calls build it. The assistant must actually complete the build and check its circuit before you claim success.
5. Open circuit details to reveal what the child just made. Share the build using the existing share button.
6. If time permits, open Secret signal and hold its button to make a sound. Release to stop. A child can invent their own tapping code.

The starter builds and manual tools work without an AI connection. Free-form AI requires the existing Vercel proxy with an OpenRouter or Gemini key. This pass verifies the agent loop with mocked responses; it does not establish live-provider accuracy or child usability.

## What this pass changes

Custom modeled invention parts, including a fan with a rotating rotor and safety grille; a closer working surface; readable controls; three starter inventions; physical inputs tied to solved current; audio for the buzzer; stable document-driven layout moves; honest assistant actions and errors; and RUN that preserves the actual creation.

The motor test models electrical current, torque, back-EMF and shaft speed. It does not simulate airflow. The circuit solver is steady-state DC: no blinking programs, general code execution, or arbitrary articulated robotics.

## The next evidence to earn

Run short supervised sessions with five kids in the target age range. Give each the same challenge: make something, change what it does, and explain the change without an adult operating the interface.

Watch for three things: whether they reach a first working invention, whether they make a second modification of their own, and whether they can explain the cause and effect. Count successful creations and self-directed remixes; do not count watching the prebuilt fan as activation. Use those sessions to choose the next invention family before broadening the product.

Avoid claiming demand, retention, educational outcomes, or school adoption from this prototype alone. The existing teacher/account layer remains available for later evaluation, but this demo should establish the child’s desire to create first.
